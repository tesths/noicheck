# 任务健康先用可轮询内部端点接外部告警

任务健康页已经能让老师在后台查看失败分类和处理中数量，但外部告警或定时通知不应直接抓取带学生、题目和失败原因的后台页面。第一步采用 token 保护的内部 JSON 端点：

```text
GET /internal/operations/health
```

端点只返回全站汇总数字和 `ok / unhealthy` 状态，不返回学生姓名、题目标题、代码或失败明细。外部监控系统可以带 `X-Internal-Job-Token` 请求该端点；如果需要用 HTTP 状态直接触发告警，可加：

```text
?fail_on_unhealthy=1
```

当存在失败任务时，该模式返回 `503`。处理中任务只计入汇总，不单独判定为 unhealthy，因为排队和运行中是正常异步状态。

暂不内置短信、邮件或企业微信推送。主动通知需要先确认接收渠道、告警阈值、值班人和误报处理方式，否则容易把临时 AI / 抓题失败变成噪音。
